# Planning: Fitur "Update Web" (Changelog / Pengumuman Aplikasi)

Dokumen ini menjelaskan cara kerja fitur **Update Web** di project `ga-web`, supaya bisa diimplementasikan ulang di website lain dengan stack serupa (Next.js App Router + Supabase + shadcn/ui + Tiptap + sonner).

> Semua path file di bawah merujuk ke repo `ga-web` sebagai **referensi**. Di project baru, sesuaikan nama tabel, role admin, tabel profil, dan layer storage.

---

## 1. Ringkasan Fitur

Halaman changelog internal. Admin memposting "update" aplikasi, semua user yang login bisa membaca, berkomentar, dan memberi reaction.

| Kemampuan | Siapa | Keterangan |
|---|---|---|
| Lihat daftar update (grid card) | Semua user login | Urut terbaru, card pertama diberi label "Terbaru" |
| Lihat detail (modal besar) | Semua user login | Thumbnail, versi, highlights, body rich text, reaction, komentar |
| Buat update | Admin | Halaman `/update-web/buat`, versi otomatis (patch +1) atau manual |
| Edit / hapus update | Admin | Edit di `/update-web/edit/[id]`, hapus dari modal detail (pakai konfirmasi) |
| Reaction emoji | Semua user login | **1 emoji aktif per user per post**, klik emoji yang sama = hapus, klik emoji lain = ganti. Ada animasi konfeti emoji |
| Komentar | Semua user login | Pakai panel diskusi yang sudah ada (jsonb + RPC) |
| Badge "ada update baru" | Semua user login | Titik merah di sidebar + banner di dashboard, per akun (bisa lintas perangkat) |
| Draft otomatis | Admin | Isi form disimpan otomatis ke localStorage (debounce 600ms) |

### Isi satu postingan
- **Versi** semantic `x.y.z` (disimpan sebagai 3 kolom int + 1 kolom generated `version`)
- **Judul**
- **Thumbnail** 16:9 (di-crop ke 1280×720 sebelum upload)
- **Highlights**: daftar poin singkat (array string) untuk card dan bagian atas detail
- **Content**: body rich text dalam format Tiptap JSON (heading, bold/italic, list, link, gambar, video upload/embed)
- **Discussions**: komentar (jsonb, append-only)

┌────────────── Supabase Postgres ──────────────────────────┐
│ update_web_posts            (RLS: read semua, write admin) │

**Prinsip keamanan:** yang benar-benar menjaga akses adalah **RLS + RPC di database**. Pengecekan admin di client (`use-update-web-admin.ts`, tombol yang disembunyikan) hanya untuk UX.

Semua query dijalankan langsung dari browser lewat supabase-js. Tidak ada API route atau Server Action khusus untuk fitur ini, kecuali untuk upload file (lihat bagian 6).

## 3. Skema Database

Referensi: `supabase/migrations/20260928000000_update_web_setup.sql` dan `supabase/migrations/20260928010000_update_web_v2_setup.sql`.

Prasyarat:
- Tabel `public.profiles(id uuid, role text, nama text, email text)` dengan `id = auth.users.id`
- Fungsi trigger generic `public.handle_updated_at()` (set `new.updated_at = now()`)

### 3.1 `update_web_posts`

```sql
create table public.update_web_posts (
  id bigint generated by default as identity primary key,
  version_major int not null,
  version_minor int not null,
  version_patch int not null,
  -- Generated supaya string versi tidak mungkin berbeda dari 3 kolom int-nya
  version text generated always as (
    version_major::text || '.' || version_minor::text || '.' || version_patch::text
  ) stored,
  title text not null,
  thumbnail_url text,
  highlights jsonb not null default '[]',   -- string[]
  content jsonb not null default '{}',      -- Tiptap JSON doc
  discussions jsonb not null default '[]',  -- komentar (append via RPC)
  created_by uuid references public.profiles(id) on delete set null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (version_major, version_minor, version_patch)
);
create index on public.update_web_posts (created_at desc);
-- + trigger before update -> handle_updated_at()
```

**RLS:**
- `select`: `authenticated` → `true`
- `insert` / `update` / `delete`: hanya jika `exists (select 1 from profiles where id = auth.uid() and role = 'admin')`

### 3.2 `update_web_post_reactions`

```sql
create table public.update_web_post_reactions (
  id bigint generated by default as identity primary key,
  post_id bigint not null references public.update_web_posts(id) on delete cascade,
  user_id uuid not null references public.profiles(id) on delete cascade,
  emoji text not null check (emoji in ('👍','❤️','🎉','😂','😮','🙏')),
  created_at timestamptz not null default now(),
  unique (post_id, user_id)          -- v2: 1 reaction per user per post
);
create index on public.update_web_post_reactions (post_id);
```

**RLS:**
- `select`: semua user `authenticated`
- `insert`: `with check (user_id = auth.uid())`
- `delete`: `using (user_id = auth.uid())`

Tidak perlu RPC di sini, karena RLS sudah mengunci `user_id` ke user yang login sehingga user tidak bisa memberi reaction atas nama orang lain.

> Catatan versi: di v1 unique-nya `(post_id, user_id, emoji)` (multi-emoji), lalu di v2 diubah ke `(post_id, user_id)`. **Di project baru langsung pakai versi v2.**

### 3.3 `update_web_seen` (status "sudah dilihat", per akun)

```sql
create table public.update_web_seen (
  user_id uuid primary key references public.profiles(id) on delete cascade,
  last_seen_post_id bigint references public.update_web_posts(id) on delete set null,
  last_seen_at timestamptz not null default now()
);
```

**RLS:** `select` / `insert` / `update` hanya untuk baris milik sendiri (`user_id = auth.uid()`).

Status ini sengaja disimpan di database, bukan localStorage, supaya badge tetap konsisten ketika user berganti perangkat atau browser.

### 3.4 RPC `create_update_web_post` (admin, penomoran versi atomic)

```sql
create or replace function public.create_update_web_post(
  p_title text, p_thumbnail_url text, p_highlights jsonb, p_content jsonb,
  p_version text default null
) returns public.update_web_posts
language plpgsql security definer set search_path = public as $$
declare v_role text; v_major int; v_minor int; v_patch int;
        v_row public.update_web_posts%rowtype;
begin
  select role into v_role from profiles where id = auth.uid();
  if v_role is distinct from 'admin' then raise exception 'Hanya admin ...'; end if;
  if p_title is null or trim(p_title) = '' then raise exception 'Judul wajib diisi.'; end if;

  if p_version is null then
    -- auto: patch +1 dari versi tertinggi; FOR UPDATE mencegah 2 admin mendapat nomor sama
    select version_major, version_minor, version_patch into v_major, v_minor, v_patch
    from update_web_posts
    order by version_major desc, version_minor desc, version_patch desc
    limit 1 for update;
    if v_major is null then v_major := 1; v_minor := 0; v_patch := 0;
    else v_patch := v_patch + 1; end if;
  else
    if p_version !~ '^\d+\.\d+\.\d+$' then raise exception 'Format versi harus x.y.z'; end if;
    v_major := split_part(p_version,'.',1)::int;
    v_minor := split_part(p_version,'.',2)::int;
    v_patch := split_part(p_version,'.',3)::int;
  end if;

  insert into update_web_posts (version_major, version_minor, version_patch,
    title, thumbnail_url, highlights, content, created_by)
  values (v_major, v_minor, v_patch, trim(p_title), p_thumbnail_url,
    coalesce(p_highlights,'[]'), coalesce(p_content,'{}'), auth.uid())
  returning * into v_row;
  return v_row;
exception when unique_violation then
  raise exception 'Versi tersebut sudah dipakai postingan lain.';
end; $$;
grant execute on function public.create_update_web_post(text,text,jsonb,jsonb,text) to authenticated;
```

Edit dan hapus **tidak** memakai RPC. Keduanya langsung `.update()` / `.delete()` ke tabel dan dilindungi RLS admin. Saat edit, versi selalu diisi manual. Bentrok versi ditangani oleh unique constraint.

### 3.5 RPC `add_update_web_post_discussion` (semua user)

`security definer`, hanya meng-append ke kolom `discussions`. RPC ini diperlukan karena policy `update` pada tabel hanya untuk admin, sementara komentar harus bisa dikirim semua user.

```sql
update update_web_posts
set discussions = coalesce(discussions,'[]') || jsonb_build_array(jsonb_build_object(
  'user_id', auth.uid(), 'user_name', <nama dari profiles>,
  'message', p_message, 'content', p_content,
  'mentions', coalesce(p_mentions,'[]'), 'attachment', p_attachment,
  'timestamp', now()))
where id = p_id;
```

Pesan ditolak jika `message`, `content`, dan `attachment` semuanya kosong. Muncul error jika post tidak ditemukan.

> Kalau project baru sudah punya sistem komentar sendiri (misalnya tabel `comments` generik), pakai sistem itu dan lewati RPC ini.

## 4. Service Layer (`services/updateWebService.ts`)

Semua fungsi memakai browser client `createClient()` dari `@/lib/supabase/client`.

| Fungsi | Implementasi |
|---|---|
| `fetchUpdateWebPosts()` | `select("*, created_by_profile:profiles(nama, email)")` order `created_at desc` |
| `fetchUpdateWebPostById(id)` | Sama, `.eq("id", id).single()`. Dipakai untuk refetch setelah komentar |
| `fetchLatestUpdateWebPost()` | `.limit(1).maybeSingle()` untuk badge dan banner |
| `fetchUpdateWebPostReactions(postIds, currentUserId)` | **1 query** `in("post_id", postIds)` dengan join `profiles(id, nama)`, lalu **diagregasi di JS** menjadi `Map<postId, {emoji, count, reactedByMe, reactors[]}[]>` |
| `setUpdateWebPostReaction(postId, userId, emoji \| null)` | `delete` baris milik user di post tersebut, lalu `insert` jika emoji tidak null |
| `fetchUpdateWebSeenState(userId)` / `markUpdateWebSeen(userId, postId)` | select / **upsert** ke `update_web_seen` |
| `createUpdateWebPost(payload)` | `rpc("create_update_web_post", …)`. `version: null` = otomatis |
| `updateUpdateWebPost(id, payload)` | `.update({...}).eq("id", id).select().single()` |
| `deleteUpdateWebPost(id)` | `.delete().eq("id", id)` |
| `addUpdateWebPostDiscussion(id, payload)` | `rpc("add_update_web_post_discussion", …)` |

## 5. Workflow per Fitur

### 5.1 Halaman list (`/update-web`)
1. Mount → `supabase.auth.getUser()` → ambil `profiles.role, nama` → set `isAdmin`, `currentUserId`, lalu `userLoaded = true`.
2. **Fetch reaction menunggu `userLoaded`**. Jika tidak, `reactedByMe` dihitung dengan userId `null` (semua bernilai false), sehingga user bisa memberi reaction dobel.
3. `loadPosts()` → fetch posts → fetch reactions untuk semua id. Pakai `loadRequestId` ref supaya response lama yang datang terlambat tidak menimpa state baru.
4. Render grid `UpdatePostCard` (skeleton saat loading, empty state jika kosong). Tombol "Buat Update" hanya muncul untuk admin.
5. Membuka halaman ini dianggap "sudah dilihat": `useUpdateWebBadge(userId)`, lalu setelah `!badgeLoading` panggil `markSeen()`.
6. Klik card membuka `UpdatePostDetailDialog`. State `selectedPost` dan reaction dikelola di halaman ini (controlled).

### 5.2 Reaction (optimistic)
1. Cari `previousEmoji` milik user. `nextEmoji = previousEmoji === emoji ? null : emoji`.
2. Jika `nextEmoji` ada, jalankan `fireEmojiConfetti(nextEmoji)` (`lib/emoji-confetti.ts`, opsional).
3. Update state lokal secara optimistic: kurangi count atau hapus reactor dari emoji lama (buang summary yang count-nya 0), lalu tambahkan ke emoji baru.
4. Panggil `setUpdateWebPostReaction`. Jika gagal, tampilkan toast error lalu `loadPosts()` untuk resync.
5. UI `UpdatePostReactions`: pill per emoji dengan count, tooltip berisi nama reactor, dan popover untuk memilih emoji. Komponennya controlled, hanya render dan memanggil callback.

### 5.3 Detail dialog
- Modal besar (`max-w-4xl lg:max-w-5xl xl:max-w-6xl max-h-[85vh] overflow-y-auto`).
- Isi (`UpdatePostArticle`, juga dipakai oleh preview): thumbnail, badge versi dan "Terbaru", judul, penulis dan tanggal, highlights, lalu `UpdatePostContentView` (Tiptap read-only).
- Reaction bar, lalu `DiscussionPanel`. Setelah submit komentar, **refetch** post dengan `fetchUpdateWebPostById`, karena RPC hanya mengembalikan void. Hasilnya dikirim ke parent lewat `onPostUpdated`.
- Khusus admin: tombol Edit (navigasi ke `/update-web/edit/[id]`) dan Hapus (AlertDialog, lalu `deleteUpdateWebPost`, `onDeleted`, dan tutup modal).

### 5.4 Buat / edit (`UpdatePostForm`, dipakai oleh `/buat` dan `/edit/[id]`)
- Guard halaman: `useUpdateWebAdmin()`. Jika bukan admin, tampilkan toast dan `router.replace("/update-web")`.
- Halaman create juga mengambil versi tertinggi untuk preview "Otomatis (akan jadi vX.Y.Z)". Nomor final tetap dihitung server.
- Form memakai `useState` biasa (tanpa react-hook-form/zod):
  - **Judul** (wajib)
  - **Versi**: checkbox "Otomatis" (khusus create) atau 3 input number major/minor/patch
  - **Highlights**: list input dinamis. Enter menambah poin baru, tombol hapus per poin, minimal 1 baris
  - **Thumbnail 16:9**: klik, drag & drop, paste (Ctrl+V atau tombol "Tempel"), lalu `ImageCropDialog` (aspect 16/9, output 1280px), lalu upload ke `update-web/thumbnails/{timestamp}_thumbnail.{ext}`
  - **Detail**: `UpdatePostEditor` (Tiptap), dengan prefix path media `update-web/posts/{id|draft}`
- **Tab Tulis / Preview**: tab tulis memakai `forceMount` + `hidden` supaya editor tidak unmount (riwayat undo dan posisi kursor tetap ada). Preview memakai `UpdatePostPreview` yang merender `UpdatePostArticle`.
- **Draft otomatis**:
  - Key: `update-web:draft:create:{userId}` atau `update-web:draft:edit:{postId}:{userId}`
  - Debounce 600ms. Jika isi sama dengan baseline (dibandingkan lewat `snapshot()` yang men-trim dan menormalkan doc kosong), draft dihapus
  - Draft dibaca sekali saat mount (sebelum editor dibuat), lalu muncul toast "Melanjutkan draft tersimpan"
  - Indikator status: "Menyimpan draft…" / "Draft tersimpan HH:MM"
  - Tombol "Kosongkan draft" / "Buang perubahan" (AlertDialog) mereset ke baseline dan me-remount editor (`editorKey++`) supaya riwayat undo ikut bersih
  - Semua akses localStorage dibungkus try/catch
  - Setelah submit sukses, `doneRef = true` supaya timer autosave yang tertunda tidak menulis ulang draft
- **Submit**: validasi judul, konten tidak kosong (doc kosong = hanya paragraf kosong), dan versi berupa integer ≥ 0. Lalu panggil create (RPC) atau update. Jika sukses: hapus draft, toast, lalu `router.push("/update-web")`.

### 5.5 Badge "update baru" (`hooks/use-update-web-badge.ts`)
```
isNew = latestPost ada
     && (now - latestPost.created_at) < 7 hari
     && (last_seen_post_id == null || last_seen_post_id < latestPost.id)
```
- Dipakai oleh **sidebar** (`badge: 1` pada item nav `/update-web`) dan **dashboard** (`UpdateWebDashboardBanner`, widget kecil dengan animasi pulse beberapa detik sekali, berisi link ke `/update-web`).
- `markSeen()` langsung set `isNew = false` di UI, lalu upsert ke DB. Error diabaikan (best-effort).
- Semua error pada hook ini diabaikan, karena badge bukan fitur kritikal.

> Catatan: pembandingan memakai `id` post. Aman selama id bertambah terus (identity). Jika project baru memakai uuid, bandingkan `created_at` atau simpan `last_seen_at`.

## 6. Editor Rich Text (Tiptap)

File:
- `components/tiptap/update-post-editor.tsx`: editor + toolbar
- `components/tiptap/update-post-content-view.tsx`: renderer read-only (`editable: false`) dengan **extension set yang sama** dengan editor (wajib, supaya semua node bisa di-parse)
- `components/tiptap/update-video-extension.tsx`: custom node `video` dengan attr `sourceType: "upload" | "embed"`. Upload dirender sebagai `<video controls>`, embed sebagai `<iframe>`. `normalizeVideoEmbedUrl()` mengubah URL YouTube/Vimeo ke format embed, URL lain dipakai apa adanya
- `components/tiptap/update-link-extension.ts`: link yang dipaste otomatis menjadi link (dengan popover untuk mengganti teks), dan mengenali sintaks markdown `[teks](url)`

Extension: `StarterKit` (heading H2/H3, bold, italic, list), `Placeholder`, `@tiptap/extension-image`, link custom, video custom.

Toolbar: Bold, Italic, H2, H3, bullet list, ordered list, link/unlink, gambar, video upload, video embed.

Media bisa masuk lewat tombol toolbar, paste dari clipboard, atau drag & drop ke area editor. Semuanya melewati satu fungsi `uploadMedia()` dengan validasi ukuran (`getAttachmentSizeError`).

Editor mengekspos handle `getJSON()` lewat `forwardRef` + `useImperativeHandle`, dipakai form saat submit supaya mendapat konten paling baru.

### Upload file
Di `ga-web`, upload memakai **signed upload URL** (`lib/uploadDirect.ts`):
1. Server Action `createSignedUploadUrl(path)` mengembalikan token, bucket, dan publicUrl.
2. Browser mengunggah langsung dengan `storage.from(bucket).uploadToSignedUrl(path, token, file)`.

Alasannya: Vercel membatasi body request Server Action/Function sebesar 4.5MB, jadi file besar (terutama video) tidak boleh lewat server.

**Di project baru:** jika memakai Supabase Storage biasa, bisa langsung `supabase.storage.from("update-web").upload(...)` dari browser dengan storage policy (insert hanya admin, read public), atau tetap memakai pola signed URL jika hosting di Vercel dan butuh file besar.

## 9. Poin Penting / Jebakan

- **Nomor versi dihitung di server** (RPC dengan `for update`). Client hanya menampilkan perkiraan. Ini mencegah race condition ketika 2 admin posting bersamaan.
- **Daftar emoji ada di 2 tempat** (CHECK constraint di DB dan konstanta TS). Keduanya harus selalu sama.
- **Tunggu auth selesai sebelum fetch reaction**, supaya nilai `reactedByMe` benar.
- **Renderer read-only harus memakai extension yang sama** dengan editor. Jika tidak, node video/link custom akan hilang saat dirender.
- **Komentar memakai RPC security definer** karena policy update tabel hanya untuk admin. Jangan membuka policy update untuk semua user.
- **Media yang sudah di-upload tidak dihapus** ketika draft dikosongkan atau post dihapus (orphan file). Jika penting, tambahkan cleanup job.
- **Badge memakai window 7 hari**, jadi post lama tidak membuat badge menyala untuk user baru.
