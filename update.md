# Fitur "Update Web" — Panduan Implementasi ke Web Lain

Dokumen ini menjelaskan fitur **Update Web** (changelog/pengumuman aplikasi internal) di `ga-web` sesuai kondisi kode saat ini. Tujuannya supaya fitur yang sama bisa dipasang di website lain dengan stack serupa.

**Stack yang dipakai:** Next.js App Router (client components) + Supabase (Postgres + RLS + RPC) + shadcn/ui + Tiptap + sonner + lucide-react.

> Semua path file merujuk ke repo `ga-web`. Di project baru, sesuaikan nama tabel profil, cara cek admin, dan layer storage.

---

## 1. Ringkasan

Admin memposting "update" aplikasi (versi, judul, thumbnail, poin singkat, isi rich text). Semua user yang login bisa membaca, memberi reaction emoji, dan berkomentar (termasuk membalas komentar). User mendapat badge "ada update baru" di sidebar dan banner di dashboard sampai mereka membuka halaman Update Web.

| Kemampuan | Siapa | Catatan |
|---|---|---|
| Lihat daftar update (grid card) | Semua user login | Urut terbaru. Card pertama diberi badge **"Versi Saat Ini"** |
| Lihat detail (modal besar) | Semua user login | Bisa dibuka lewat deep link `/update-web?post=<id>` |
| Buat update | Admin | `/update-web/buat`. Versi otomatis (patch +1) atau manual |
| Edit / hapus update | Admin | `/update-web/edit/[id]`. Hapus dari modal detail, dengan konfirmasi |
| Reaction emoji | Semua user login | **1 emoji aktif per user per post.** Klik emoji yang sama = hapus, klik emoji lain = ganti. Ada efek konfeti |
| Komentar + balas komentar | Semua user login | Pemilik komentar yang dibalas mendapat notifikasi |
| Badge "update baru" | Semua user login | Titik merah di sidebar + banner dashboard. Status disimpan per akun di DB |
| Draft otomatis | Admin | Isi form disimpan ke localStorage (debounce 600ms) |

### Isi satu postingan
- **Versi** semantic `x.y.z`: 3 kolom int + 1 kolom generated `version`
- **Judul**
- **Thumbnail** 16:9, di-crop ke 1280×720 sebelum upload
- **Highlights**: array string berisi poin singkat (tampil di card dan bagian atas detail)
- **Content**: dokumen Tiptap JSON (H2/H3, bold, italic, list, link, gambar, video upload/embed)
- **Discussions**: komentar dalam kolom jsonb, append-only lewat RPC

## 3. Database (migration gabungan, siap pakai)

Di `ga-web` skemanya tersebar di 3 migration:
- `supabase/migrations/20260928000000_update_web_setup.sql` (v1)
- `supabase/migrations/20260928010000_update_web_v2_setup.sql` (reaction 1 per user + tabel seen)
- `supabase/migrations/20260930020000_discussion_reply_setup.sql` (balas komentar)

Untuk project baru, **langsung pakai versi gabungan di bawah**.

**Prasyarat:**
- Tabel `public.profiles(id uuid = auth.users.id, role text, nama text, email text)`
- Fungsi trigger generic `public.handle_updated_at()` yang menjalankan `new.updated_at = now()`

```sql
-- ============================================================
-- 0. (Jika belum ada) trigger updated_at generic
-- ============================================================
create or replace function public.handle_updated_at()
returns trigger language plpgsql as $$
begin
  new.updated_at = now();
  return new;
end; $$;

-- ============================================================
-- 1. update_web_posts
-- ============================================================
create table if not exists public.update_web_posts (
  id bigint generated by default as identity primary key,
  version_major int not null,
  version_minor int not null,
  version_patch int not null,
  -- generated: string versi tidak mungkin berbeda dari 3 kolom int-nya
  version text generated always as (
    version_major::text || '.' || version_minor::text || '.' || version_patch::text
  ) stored,
  title text not null,
  thumbnail_url text,
  highlights jsonb not null default '[]',   -- string[]
  content jsonb not null default '{}',      -- Tiptap JSON doc
  discussions jsonb not null default '[]',  -- komentar (append via RPC)
  created_by uuid references public.profiles(id) on delete set null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (version_major, version_minor, version_patch)
);

create index if not exists idx_update_web_posts_created_at
  on public.update_web_posts (created_at desc);

drop trigger if exists on_update_web_posts_updated on public.update_web_posts;
create trigger on_update_web_posts_updated
  before update on public.update_web_posts
  for each row execute function public.handle_updated_at();

alter table public.update_web_posts enable row level security;

create policy "update_web_posts_select" on public.update_web_posts
  for select to authenticated using (true);

create policy "update_web_posts_insert_admin" on public.update_web_posts
  for insert to authenticated
  with check (exists (select 1 from public.profiles p where p.id = auth.uid() and p.role = 'admin'));

create policy "update_web_posts_update_admin" on public.update_web_posts
  for update to authenticated
  using (exists (select 1 from public.profiles p where p.id = auth.uid() and p.role = 'admin'))
  with check (exists (select 1 from public.profiles p where p.id = auth.uid() and p.role = 'admin'));

create policy "update_web_posts_delete_admin" on public.update_web_posts
  for delete to authenticated
  using (exists (select 1 from public.profiles p where p.id = auth.uid() and p.role = 'admin'));

-- ============================================================
-- 2. update_web_post_reactions (1 reaction per user per post)
-- ============================================================
create table if not exists public.update_web_post_reactions (
  id bigint generated by default as identity primary key,
  post_id bigint not null references public.update_web_posts(id) on delete cascade,
  user_id uuid not null references public.profiles(id) on delete cascade,
  -- HARUS sama dengan UPDATE_WEB_REACTION_EMOJIS di type/update-web.ts
  emoji text not null check (emoji in ('👍', '❤️', '🎉', '😂', '😮', '🙏')),
  created_at timestamptz not null default now(),
  unique (post_id, user_id)
);

create index if not exists idx_update_web_post_reactions_post
  on public.update_web_post_reactions (post_id);

alter table public.update_web_post_reactions enable row level security;

create policy "update_web_post_reactions_select" on public.update_web_post_reactions
  for select to authenticated using (true);

-- Tidak perlu RPC: user_id dikunci ke auth.uid(), jadi user tidak bisa
-- memberi reaction atas nama orang lain.
create policy "update_web_post_reactions_insert_own" on public.update_web_post_reactions
  for insert to authenticated with check (user_id = auth.uid());

create policy "update_web_post_reactions_delete_own" on public.update_web_post_reactions
  for delete to authenticated using (user_id = auth.uid());

-- ============================================================
-- 3. update_web_seen (status "sudah dilihat", per akun, lintas device)
-- ============================================================
create table if not exists public.update_web_seen (
  user_id uuid primary key references public.profiles(id) on delete cascade,
  last_seen_post_id bigint references public.update_web_posts(id) on delete set null,
  last_seen_at timestamptz not null default now()
);

alter table public.update_web_seen enable row level security;

create policy "update_web_seen_select_own" on public.update_web_seen
  for select to authenticated using (user_id = auth.uid());
create policy "update_web_seen_insert_own" on public.update_web_seen
  for insert to authenticated with check (user_id = auth.uid());
create policy "update_web_seen_update_own" on public.update_web_seen
  for update to authenticated using (user_id = auth.uid()) with check (user_id = auth.uid());

-- ============================================================
-- 4. RPC create_update_web_post (admin, nomor versi atomic)
-- ============================================================
-- p_version null  -> patch +1 dari versi tertinggi (1.0.0 jika belum ada post).
--                    FOR UPDATE mencegah 2 admin mendapat nomor yang sama.
-- p_version "x.y.z" -> manual, formatnya divalidasi di server.
create or replace function public.create_update_web_post(
  p_title text,
  p_thumbnail_url text,
  p_highlights jsonb,
  p_content jsonb,
  p_version text default null
)
returns public.update_web_posts
language plpgsql security definer set search_path = public
as $$
declare
  v_role text; v_major int; v_minor int; v_patch int;
  v_row public.update_web_posts%rowtype;
begin
  select role into v_role from public.profiles where id = auth.uid();
  if v_role is distinct from 'admin' then
    raise exception 'Hanya admin yang boleh membuat postingan Update Web.';
  end if;
  if p_title is null or trim(p_title) = '' then
    raise exception 'Judul wajib diisi.';
  end if;

  if p_version is null then
    select version_major, version_minor, version_patch
      into v_major, v_minor, v_patch
    from public.update_web_posts
    order by version_major desc, version_minor desc, version_patch desc
    limit 1
    for update;

    if v_major is null then
      v_major := 1; v_minor := 0; v_patch := 0;
    else
      v_patch := v_patch + 1;
    end if;
  else
    if p_version !~ '^\d+\.\d+\.\d+$' then
      raise exception 'Format versi harus x.y.z (mis. 1.4.2).';
    end if;
    v_major := split_part(p_version, '.', 1)::int;
    v_minor := split_part(p_version, '.', 2)::int;
    v_patch := split_part(p_version, '.', 3)::int;
  end if;

  insert into public.update_web_posts (
    version_major, version_minor, version_patch,
    title, thumbnail_url, highlights, content, created_by
  ) values (
    v_major, v_minor, v_patch,
    trim(p_title), p_thumbnail_url, coalesce(p_highlights, '[]'::jsonb),
    coalesce(p_content, '{}'::jsonb), auth.uid()
  )
  returning * into v_row;

  return v_row;
exception
  when unique_violation then
    raise exception 'Versi tersebut sudah dipakai postingan lain.';
end;
$$;

grant execute on function public.create_update_web_post(text, text, jsonb, jsonb, text) to authenticated;

-- ============================================================
-- 5. RPC add_update_web_post_discussion (semua user, + reply)
-- ============================================================
-- Perlu RPC karena policy UPDATE tabel hanya untuk admin. Fungsi ini
-- security definer dan HANYA menyentuh kolom `discussions`.
create or replace function public.add_update_web_post_discussion(
  p_id bigint,
  p_message text,
  p_content jsonb default null,
  p_mentions jsonb default '[]'::jsonb,
  p_attachment jsonb default null,
  p_reply_to jsonb default null
)
returns void
language plpgsql security definer set search_path = public
as $$
declare
  v_name text;
  v_reply_to jsonb;
begin
  if trim(coalesce(p_message, '')) = '' and p_content is null and p_attachment is null then
    raise exception 'Pesan tidak boleh kosong.';
  end if;

  select coalesce(nama, email, 'Unknown User') into v_name
  from public.profiles where id = auth.uid();

  -- Whitelist key + batasi panjang, supaya client tidak bisa menyisipkan field lain
  if p_reply_to is not null and jsonb_typeof(p_reply_to) = 'object' then
    v_reply_to := jsonb_build_object(
      'user_id',   p_reply_to->>'user_id',
      'user_name', left(coalesce(p_reply_to->>'user_name', ''), 200),
      'timestamp', p_reply_to->>'timestamp',
      'excerpt',   left(coalesce(p_reply_to->>'excerpt', ''), 200)
    );
  end if;

  update public.update_web_posts
  set discussions = coalesce(discussions, '[]'::jsonb) || jsonb_build_array(
    jsonb_strip_nulls(jsonb_build_object('reply_to', v_reply_to)) ||
    jsonb_build_object(
      'user_id', auth.uid(),
      'user_name', v_name,
      'message', p_message,
      'content', p_content,
      'mentions', coalesce(p_mentions, '[]'::jsonb),
      'attachment', p_attachment,
      'timestamp', now()
    )
  )
  where id = p_id;

  if not found then
    raise exception 'Postingan Update Web tidak ditemukan.';
  end if;
end;
$$;

grant execute on function public.add_update_web_post_discussion(bigint, text, jsonb, jsonb, jsonb, jsonb) to authenticated;
```

**Catatan:**
- Edit dan hapus post **tidak** memakai RPC. Keduanya langsung `.update()` / `.delete()` dan dilindungi RLS admin. Bentrok versi saat edit ditangani unique constraint.
- Jika role admin di project baru disimpan di tempat lain (misalnya custom claim JWT atau tabel `user_roles`), ganti semua `exists (select 1 from profiles ... role = 'admin')` dan pengecekan `v_role` di RPC.
- Jika project baru sudah punya sistem komentar sendiri (misalnya tabel `comments` generik), lewati RPC nomor 5 dan kolom `discussions`.

## 5. Service layer (`services/updateWebService.ts`)

Semua fungsi memakai browser client `createClient()` dari `@/lib/supabase/client` dan melempar `error` Supabase apa adanya (caller yang menampilkan toast).

| Fungsi | Implementasi |
|---|---|
| `fetchUpdateWebPosts()` | `select("*, created_by_profile:profiles(nama, email)")`, order `created_at desc` |
| `fetchUpdateWebPostById(id)` | Sama, `.eq("id", id).single()`. Dipakai halaman edit dan refetch setelah komentar |
| `fetchLatestUpdateWebPost()` | `.limit(1).maybeSingle()`. Dipakai badge, banner, dan preview versi otomatis |
| `fetchUpdateWebPostReactions(postIds, currentUserId)` | **1 query** `.in("post_id", postIds)` dengan select `post_id, emoji, user:profiles(id, nama)`, lalu diagregasi di JS menjadi `Map<postId, Summary[]>` |
| `setUpdateWebPostReaction(postId, userId, emoji \| null)` | `delete` baris milik user di post itu, lalu `insert` jika `emoji` tidak null |
| `fetchUpdateWebSeenState(userId)` | select `last_seen_post_id` (`maybeSingle`) |
| `markUpdateWebSeen(userId, postId)` | `upsert({ user_id, last_seen_post_id, last_seen_at })` |
| `createUpdateWebPost(payload)` | `rpc("create_update_web_post", { p_title, p_thumbnail_url, p_highlights, p_content, p_version })`. `version: null` berarti otomatis |
| `updateUpdateWebPost(id, payload)` | `.update({...}).eq("id", id).select().single()`. Versi dikirim sebagai 3 int |
| `deleteUpdateWebPost(id)` | `.delete().eq("id", id)` (reaction ikut terhapus lewat cascade) |
| `addUpdateWebPostDiscussion(id, payload)` | `rpc("add_update_web_post_discussion", ...)`. `p_reply_to` **hanya dikirim jika memang membalas** |

## 6. Halaman & alur kerja

### 6.1 Halaman list — `/update-web`
1. Saat mount: `supabase.auth.getUser()`, lalu ambil `profiles.role, nama`. Set `currentUserId`, `currentUserName`, `isAdmin`. Di blok `finally`, set `userLoaded = true`.
2. **Fetch post + reaction baru dijalankan setelah `userLoaded`.** Jika tidak, `reactedByMe` dihitung dengan userId `null` (semuanya false) dan user bisa memberi reaction dobel.
3. `loadPosts()` memakai ref `loadRequestId`. Response dari request lama diabaikan supaya tidak menimpa state yang lebih baru.
4. Tampilan: grid `UpdatePostCard` (1/2/3 kolom), 6 skeleton saat loading, empty state dengan ikon `Megaphone`. Tombol "Buat Update" hanya muncul untuk admin.
5. **Mark seen:** `useUpdateWebBadge(currentUserId)`. Setelah `!badgeLoading`, panggil `markSeen()`. Membuka halaman ini berarti user sudah melihat update.
6. **Deep link:** setelah daftar termuat, baca `?post=<id>` dan buka modal detail post tersebut, sekali saja (dijaga ref). Dipakai oleh link notifikasi balasan komentar.
7. State `selectedPost` dan reaction dikelola di halaman ini. Card dan dialog bersifat controlled.

### 6.2 Reaction (optimistic)
```ts
const previousEmoji = current.find((s) => s.reactedByMe)?.emoji ?? null;
const nextEmoji = previousEmoji === emoji ? null : emoji; // emoji sama = hapus
if (nextEmoji) fireEmojiConfetti(nextEmoji);
// 1. state lokal: kurangi emoji lama (buang summary yang count-nya 0),
//    lalu tambahkan ke emoji baru (atau buat summary baru)
// 2. await setUpdateWebPostReaction(postId, userId, nextEmoji)
// 3. jika gagal: toast error + loadPosts() untuk resync
```
Komponen `UpdatePostReactions` berisi pill per emoji (count, plus highlight jika `reactedByMe`), tooltip berisi nama reactor ("A, B, C, dan N lainnya"), dan popover `SmilePlus` untuk memilih 6 emoji. Semua klik memakai `e.stopPropagation()` supaya card tidak ikut terbuka.

`lib/emoji-confetti.ts` (opsional) adalah efek konfeti tanpa library: satu `<canvas>` fixed full-screen dengan `pointer-events: none`, dua "meriam" dari pojok kiri bawah dan kanan bawah, sprite emoji di-cache, dan canvas dilepas otomatis ketika semua partikel habis.

### 6.3 Card — `UpdatePostCard`
Berisi thumbnail `aspect-video` (atau placeholder "Tidak ada thumbnail"), badge `v{version}` + "Versi Saat Ini" untuk post pertama, tanggal format `id-ID`, judul (`line-clamp-2`), maksimal 3 highlight lalu "+N lainnya", bar reaction, dan jumlah komentar.

### 6.4 Detail dialog — `UpdatePostDetailDialog`
- Ukuran: `max-w-4xl lg:max-w-5xl xl:max-w-6xl max-h-[85vh] overflow-y-auto`.
- Header: badge versi, "Versi Saat Ini", judul, lalu "Diposting {tanggal} oleh {nama}".
- Tombol Edit dan Hapus khusus admin. Hapus memakai `AlertDialog`, lalu `deleteUpdateWebPost`, toast, menutup modal, dan memanggil `onDeleted`.
- Isi: `UpdatePostArticle` (thumbnail, highlights, `UpdatePostContentView`). Komponen yang sama dipakai untuk preview di form.
- `UpdatePostReactions`, lalu `DiscussionPanel` dengan `allowReply` dan `storagePathPrefix = update-web/discussions/{postId}`.
- **Submit komentar:**
  1. `addUpdateWebPostDiscussion(post.id, payload)`
  2. Jika `payload.reply_to.user_id` ada, **bukan diri sendiri**, dan **belum di-mention** di komentar itu, kirim notifikasi `type: "reply"` dengan link `/update-web?post={id}`
  3. Refetch dengan `fetchUpdateWebPostById` (karena RPC mengembalikan void), lalu `onPostUpdated(refreshed)`

### 6.5 Form buat/edit — `UpdatePostForm`
Dipakai oleh `/update-web/buat` (mode `create`) dan `/update-web/edit/[id]` (mode `edit`).

- **Guard:** `useUpdateWebAdmin()`. Jika user tidak login atau bukan admin, tampilkan toast lalu `router.replace("/update-web")`. Selama pengecekan, tampilkan Skeleton.
- Halaman **buat** mengambil `fetchLatestUpdateWebPost()` untuk teks "Otomatis (akan jadi vX.Y.Z)". Nomor final tetap dihitung server.
- Halaman **edit** memvalidasi `id` (harus integer), memanggil `fetchUpdateWebPostById`, dan menampilkan pesan error + tombol kembali jika gagal.
- Form memakai `useState` biasa (tanpa react-hook-form/zod):
  - **Judul** (wajib)
  - **Versi**: checkbox "Otomatis" (hanya di mode create), atau 3 input number major/minor/patch
  - **List Update Singkat (highlights)**: input dinamis. Enter menambah poin baru, ada tombol hapus per poin, minimal 1 baris
  - **Thumbnail 16:9**: klik, drag & drop, paste (Ctrl+V atau tombol "Tempel"), lalu `ImageCropDialog` (`aspect 16/9`, `outputWidth 1280`), lalu upload ke `update-web/thumbnails/{Date.now()}_thumbnail.{jpg|webp}`. Ada tombol Ganti/Hapus saat hover
  - **Detail**: `UpdatePostEditor` dengan `storagePathPrefix = update-web/posts/{id|draft}`
- **Tab Tulis / Preview.** Tab Tulis memakai `forceMount` + class `hidden`, supaya editor tidak unmount dan riwayat undo serta posisi kursor tetap ada.
- **Draft otomatis (localStorage):**
  - Key: `update-web:draft:create:{userId}` atau `update-web:draft:edit:{postId}:{userId}`
  - Debounce 600ms. Jika isi form sama dengan baseline (dibandingkan lewat `snapshot()` yang men-trim teks, membuang highlight kosong, dan menormalkan doc kosong), draft dihapus
  - Draft dibaca sekali lewat lazy `useState` sebelum editor dibuat, lalu muncul toast "Melanjutkan draft tersimpan"
  - Indikator: "Menyimpan draft…" atau "Draft tersimpan HH:MM"
  - Tombol "Kosongkan draft" / "Buang perubahan" (AlertDialog) mereset ke baseline dan menjalankan `editorKey++` untuk remount editor, supaya riwayat undo ikut bersih
  - Semua akses localStorage dibungkus try/catch
  - Setelah submit sukses, `doneRef.current = true` supaya timer autosave yang tertunda tidak menulis draft lagi
- **Submit:**
  1. Judul tidak boleh kosong
  2. Konten diambil dari `editorRef.current.getJSON()` (paling baru) dan tidak boleh kosong. Doc dianggap kosong jika hanya berisi paragraf kosong
  3. Versi manual harus integer ≥ 0
  4. Highlights di-trim dan yang kosong dibuang
  5. Create memakai RPC (`version: null` jika otomatis). Edit memakai `.update()`
  6. Jika sukses: hapus draft, tampilkan toast, lalu `router.push("/update-web")`

### 6.6 Badge "update baru" — `hooks/use-update-web-badge.ts`
```
isNew = latestPost ada
     && (now - latestPost.created_at) < 7 hari
     && (last_seen_post_id == null || last_seen_post_id < latestPost.id)
```
- Hook mengembalikan `{ latestPost, isNew, loading, markSeen }`.
- `markSeen()` langsung set `isNew = false` di UI, lalu upsert ke DB. Semua error diabaikan (badge tidak kritikal).

### Upload file
`ga-web` memakai **signed upload URL** ke storage Supabase **terpisah (VPS)**:
1. Server Action `createSignedUploadUrl(path)` (`services/storageService.ts`) mengecek `auth.getUser()`, men-sanitize path, membuat signed upload URL, lalu mengembalikan `{ path, token, bucket, publicUrl }`.
2. Browser mengunggah langsung: `storage.from(bucket).uploadToSignedUrl(path, token, file)` (`lib/uploadDirect.ts`).

Alasannya: Vercel membatasi body Server Action/Function sebesar 4.5MB, jadi file besar (terutama video) tidak boleh lewat server.

**Opsi di project baru:**
- **Sederhana:** upload langsung dari browser `supabase.storage.from("update-web").upload(path, file)`, lalu `getPublicUrl`. Buat bucket public dengan storage policy *insert = admin saja, read = public* (untuk lampiran komentar, insert = semua user login).
- **File besar / di Vercel:** pakai pola signed URL seperti di atas.

## 11. Poin penting / jebakan

- **Nomor versi dihitung di server** (RPC + `for update`). Client hanya menampilkan perkiraan, sehingga race condition saat 2 admin posting bersamaan bisa dicegah.
- **Daftar emoji ada di 2 tempat** (CHECK constraint DB dan konstanta TS). Keduanya harus selalu sama.
- **Tunggu auth selesai sebelum fetch reaction**, supaya nilai `reactedByMe` benar.
- **Ganti reaction = delete lalu insert** (2 request, tidak atomic). Jika insert gagal, reaction lama sudah terhapus. UI menangani ini dengan resync `loadPosts()`. Jika ingin atomic, buat RPC `set_reaction` atau pakai `upsert` dengan `onConflict: "post_id,user_id"` (tambahkan policy `update` milik sendiri).
- **Renderer read-only harus memakai extension yang sama** dengan editor. Jika tidak, node `video` akan hilang saat dirender.
- **Komentar memakai RPC security definer.** Jangan membuka policy UPDATE tabel post untuk semua user.
- **`p_reply_to` hanya dikirim jika memang membalas**, supaya komentar biasa tetap jalan di DB yang belum menerima migration reply. Di project baru (SQL gabungan) hal ini tidak masalah.
- **Ubah signature RPC = drop dulu fungsi lamanya.** Jika tidak, Postgres membuat overload dan panggilan PostgREST bisa ambigu.
- **Badge membandingkan `id` post.** Ini aman karena id adalah identity yang terus naik. Jika project baru memakai uuid, bandingkan `created_at` atau simpan `last_seen_at`.
- **Badge memakai window 7 hari**, jadi post lama tidak membuat badge menyala untuk user baru.
- **Media orphan:** file yang sudah di-upload tidak dihapus ketika draft dikosongkan, thumbnail diganti, atau post dihapus. Tambahkan cleanup job jika storage perlu dihemat.
